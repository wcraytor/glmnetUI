# CLAUDE.md — glmnetUI

Project-level instructions for Claude Code when working on this repository.

## Project Overview

**glmnetUI** is an R CRAN package providing a Shiny-based GUI for elastic
net regression modeling using [glmnet](https://CRAN.R-project.org/package=glmnet).

## Build & Test

```bash
# Run the Shiny app (port 7879) via devtools
Rscript -e 'devtools::load_all(); glmnetUI(launch.browser = TRUE)'

# Install package locally (never use quick=TRUE — it skips inst/ updates)
R CMD INSTALL .

# Rebuild roxygen docs + NAMESPACE
Rscript -e 'roxygen2::roxygenise()'

# Run tests (use devtools::test, which load_all()s the package first;
# testthat::test_dir does not auto-load and will fail on internal symbols)
```

## Key Conventions

- **Purpose modes**: Radio button (`input$purpose`) with three options:
  `"general"`, `"appraisal"`, `"market"`. Controls sidebar visibility,
  subject row handling, and download workflows. Last-used purpose persisted
  via localStorage (`glmnetUI_last_purpose`).
- **Purpose change resets imports**: When purpose changes, both the data
  import (Section 1) and earth import (Section 2) are cleared — reactive
  state and UI elements (fileInput display, earth path display).
- **Earth import**: Uses `shinyFiles::shinyFilesButton` styled to match
  the native Shiny `fileInput` appearance via CSS class
  `.glmnet-earth-browse .shinyFiles`.
- **Dark mode**: Toggle button sends `dark_mode` input to server, which
  calls `session$setCurrentTheme(nord_dark)`. JS sets
  `data-glmnet-theme="dark"` attribute on body for CSS overrides.
- **Settings persistence**: glmnet call parameters, variable config, and
  interaction matrix state saved to localStorage keyed by filename + purpose.
- **CSS classes**: Use `glmnet-` prefix for custom classes.
- **Internal helpers**: Use trailing underscore: `glmnet_font_family_()`.
- **Port**: Fixed port 7879.

## Shared UI Conventions (earthUI, glmnetUI, mgcvUI)

These conventions apply consistently across all three sibling apps:

- **Nord Theme**: All UI colors must come from the official Nord palette
  (nord0–nord15). See https://www.nordtheme.com/docs/colors-and-palettes.
  Light mode uses Snow Storm base (nord6 bg, nord0 fg). Dark mode uses
  Polar Night base (nord0 bg, nord4 fg). Frost for accents, Aurora only
  for warnings/errors (alerts, validation messages), never on buttons.
- **Button classes**: Interactive buttons use Frost colors only:
  `btn-primary`, `btn-secondary`, `btn-outline-primary`,
  `btn-outline-secondary`. Never use `btn-success`, `btn-danger`,
  `btn-outline-success`, or `btn-outline-danger` on buttons.
- **Purpose persistence**: Last-used purpose is saved to localStorage
  (`glmnetUI_last_purpose`) on change and restored on `shiny:connected`.
  Each app uses its own key so they persist independently.
- **sales_grid.R exception**: Excel export colors follow third-party
  conventions, not the Nord palette.
- **renderPlot normalization**: All `renderPlot()` calls use
  `plot_dims_(session, id)` helper + fixed `res = 96`. The helper reads
  `session$clientData` width/height (which already includes
  `devicePixelRatio`), so plots self-correct across macOS, Windows,
  and Linux. Defined in `R/utils.R`; also locally in `inst/app/server.R`
  for non-module context. Pattern:
  ```r
  d_ <- plot_dims_(session, "output_id")
  output$output_id <- shiny::renderPlot({ ... },
    width = d_$width, height = d_$height, res = 96)
  ```
  Never set `res` to anything other than 96. Never omit width/height.

## Common Pitfalls

- Never use `devtools::install(quick = TRUE)` — it skips `inst/` file
  updates.
- Kill port 7879 before relaunching: `lsof -ti:7879 | xargs kill`.
- Earth provides basis definitions; glmnetUI provides data for fitting.
  Use glmnetUI's data, not earth's stored data.
- `hinge_var_` must handle `h(-121.45-var)` with negative knots.
- **R `tryCatch` scoping bug**: `doc <- ...` inside `tryCatch({...})`
  silently writes to a local copy when nested inside `for` loops
  within Shiny `observeEvent` callbacks. The outer variable is never
  updated — no error, no warning. **Workaround**: never mix mutable
  state (`doc <-`) with `tryCatch`. Instead, do pure
  computation/file-generation inside `tryCatch` (return data or
  NULL), then do all state updates (`doc <-`) in straight-line code
  outside the `tryCatch`. This applies to all three sibling apps.
- **Shiny scoping traps**: `observeEvent`, `observe`, `reactive`,
  `renderUI`, and `renderPlot` all create function scopes.
  Assigning to a local variable inside these (especially when
  nested with `tryCatch` or `for` loops) silently creates a local
  copy — the outer scope is never updated. Use `reactiveVal` or
  `reactiveValues` for shared state, and call `rv(new_value)` not
  `rv <- new_value` (the latter silently overwrites the reactive
  with a plain value). Same workaround: keep `tryCatch` for pure
  computation only; do all side effects in straight-line code.
